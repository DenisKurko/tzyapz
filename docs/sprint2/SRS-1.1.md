## 1. Вступ

### 1.1 Призначення

Документ визначає вимоги до вебзастосунку «ФінКит» — кабінету онлайн-банкінгу для фізичних осіб компанії «ФінКит Банк» — та до модуля бізнес-логіки нової функції «Кредитний калькулятор і заявка онлайн». Призначений для відділу забезпечення якості, розробників модуля та замовника як підстава приймання.

### 1.2 Обсяг

До обсягу входять функції кабінету клієнта від реєстрації до виходу та звернення до служби підтримки (розділ 3), а також правила модуля бізнес-логіки: кредитний калькулятор, валідатор переказів, книга обліку рахунку (розділ 5). Поза обсягом: мобільний застосунок, робочі місця операціоніста та ризик-менеджера, карткові продукти, сповіщення e-mail/SMS.

### 1.3 Терміни і скорочення

| Термін | Визначення |
| --- | --- |
| Клієнт | Фізична особа з обліковим записом у «ФінКит» і щонайменше одним рахунком. |
| Кабінет клієнта | Сторінки, доступні після входу: рахунки, операції, налаштування. |
| Публічна сторінка | Сторінка, доступна без входу: головна, «Про нас», «Послуги», «Контакти», «Реєстрація», «Пошук клієнта» (перелік потребує підтвердження замовником). *Нове, дефект 20.* |
| Рахунок | Поточний (checking), ощадний (savings) або кредитний (loan) рахунок клієнта з балансом у гривнях; кредитний рахунок створюється лише за F-110. *Змінено, дефект 2.* |

### 1.4 Посилання

- Каталог продуктів — картка продукту П2 «ФінКит».
- Модуль бізнес-логіки «ФінКит» версії 1.0.0 — README.md у `code/modules/finkit/v1/`.
- Поточна версія продукту (demo): parabank.parasoft.com; резерв — GlobalSQA Banking Project.
- Реєстр дефектів вимог SRS 1.0 — підстава змін версії 1.1.

## 2. Загальний опис

### 2.1 Користувачі та ролі

| Роль | Що робить у системі |
| --- | --- |
| Клієнт | Реєструється, входить і виконує всі операції кабінету за розділом 3. |
| Операціоніст | Обслуговує клієнтів у відділенні; у поточній версії окремого робочого місця не має. |
| Ризик-менеджер | У поточній версії окремого робочого місця не має; параметри автоматичного кредитного рішення задає адміністратор (2.3 п. 5). *Змінено, дефект 5.* |
| Адміністратор | Сторінка адміністрування: ініціалізація та очищення даних (F-150), параметри кредитного рішення (F-160), параметри застосунку. *Змінено, дефект 39.* |

### 2.2 Середовище

Вебзастосунок для браузерів Chrome і Firefox двох останніх стабільних мажорних версій на дату випуску версії продукту; поточна версія розгорнута за адресою з розділу 1.4. Модуль бізнес-логіки — бібліотека Java 17 (Maven 3.9, без зовнішніх залежностей у робочому коді; тести — JUnit 5). *Змінено, дефект 6.*

### 2.3 Обмеження і припущення

1. Усі суми — у гривнях з точністю до копійки; символ «$» у поточній версії читати як «грн» 1:1.
2. Дані поточної версії періодично скидаються: створені під час тестування облікові записи і рахунки можуть зникнути.
3. Мова інтерфейсу поточної версії — англійська; підписи і повідомлення в документі — їх українські еквіваленти.
4. Поле «РНОКПП» відповідає полю SSN, «Область» — State, «Поштовий індекс» — Zip Code.
5. Параметри автоматичного кредитного рішення — спосіб опрацювання заявки і поріг — задає адміністратор на сторінці адміністрування (F-160). За замовчуванням спосіб опрацювання — «перший внесок», поріг — 20 %: заявку схвалено, якщо перший внесок становить не менше 20 % суми кредиту і не перевищує доступну суму рахунку списання (потребує підтвердження замовником). *Змінено, дефекти 5, 7.*
6. Сповіщення e-mail та SMS не надсилаються; підтвердження показуються на сторінці.

## 5. Вимоги до бізнес-логіки модуля

Модуль — окремий Maven-проєкт (пакет `ua.kpi.tzyapz.finkit`, класи `LoanCalculator`, `TransferValidator`, `AccountLedger`). Усі грошові величини — тип `java.math.BigDecimal`; результати округлюються до двох знаків після коми (копійок) за правилом HALF\_UP; проміжні обчислення не округлюються. Позначення: P — сума кредиту (грн), r — річна ставка (%), n — строк (місяців), i — місячна ставка у частках, A — щомісячний платіж (грн).

| ID | Формулювання | Пріоритет |
| --- | --- | --- |
| BL-10 | `LoanCalculator.monthlyPayment(principal, annualRatePercent, months)` обчислює щомісячний ануїтетний платіж за формулою A = P · i / (1 − (1 + i)^(−n)), де i = r / 12 / 100. Результат — `BigDecimal` із двома знаками після коми, округлення HALF\_UP. | High |
| BL-20 | `LoanCalculator.totalInterest(principal, annualRatePercent, months)` повертає загальну переплату A · n − P, де A — округлений результат BL-10; результат округлюється до двох знаків HALF\_UP. | Medium |
| BL-30 | Обидва методи `LoanCalculator` приймають лише P у межах 1 000..1 000 000 грн, n у межах 3..60 місяців, r у межах 5..40 % (усі межі включно); для будь-якого значення поза межами метод кидає `IllegalArgumentException`. | High |
| BL-40 | `TransferValidator.validate(fromIban, toIban, amount, balance, todaySpent)` дозволяє переказ лише за одночасного виконання умов: amount > 0; amount ≤ balance; todaySpent + amount ≤ 50 000 грн (денний ліміт); fromIban ≠ toIban. Результат — перелік кодів порушень (`AMOUNT_NOT_POSITIVE`, `INSUFFICIENT_FUNDS`, `DAILY_LIMIT_EXCEEDED`, `SAME_ACCOUNT`); порожній перелік означає, що переказ дозволено. | High |
| BL-50 | IBAN рахунку-джерела та рахунку-одержувача має відповідати українському формату; рядок іншого вигляду вважається недійсним (коди `INVALID_FROM_IBAN`, `INVALID_TO_IBAN`). | High |
| BL-60 | `TransferValidator` перевіряє лише формат IBAN за BL-50 і не перевіряє існування рахунку-одержувача — це виконує процесинговий центр банку поза модулем. Модуль не використовує мережевих з'єднань і не має зовнішніх залежностей. *Змінено, дефект 30.* | Medium |
| BL-70 | `AccountLedger.deposit(amount)` збільшує баланс рахунку, `withdraw(amount)` — зменшує; сума кожної операції має бути додатною: для нульової або від'ємної суми метод кидає `IllegalArgumentException`, а баланс не змінюється. Якщо сума `withdraw` перевищує поточний баланс, метод кидає виняток, баланс не змінюється (тип винятку звірити з README модуля v1). `balance()` повертає поточний баланс; баланс нового рахунку — 0,00 грн. *Змінено, дефект 31.* | High |
