## 2.3. Схема ідентифікаторів

| Об'єкт | Формат | Правило |
|---|---|---|
| Тест-кейс | `TC-001` … `TC-061` | наскрізна нумерація в межах спринту; ідентифікатор не змінюється і не перевикористовується |
| Вимога | `F-10`, `GUI-30`, `BL-40`, `P-10`, `S-10`, `U-10`, `D-10` | ідентифікатори SRS 1.1 без змін; кожна вимога має кейс або причину в розділі 2.2 |
| Дефект | `BUG-001` … `BUG-023` | наскрізна нумерація в межах спринту; звіт живе в реєстрі `bug-reports.md` |
| Вкладення | `BUG-<номер>-<порядковий>.png` | кожен файл згаданий у тексті свого звіту |
| Виконання | `Run 1` … `Run 6` | рядок журналу — одне виконання одного кейса; один кейс може мати кілька рядків |

Трекер дефектів — файл `bug-reports.md`: п. 4.15 методички допускає таблицю з тими самими полями замість GitHub Issues, тому Bug ID є самостійним ідентифікатором у реєстрі.

**Run 4 і версія 2.2.** У Run 4 реєстрація за текстом кейсів не виконувалась. Причини локалізовано перевіркою по одному параметру: demo не приймає логін довший за 20 символів (BUG-019) і довгі кириличні значення імені й адреси (BUG-020), відповідаючи в обох випадках хибним «This username already exists.». SRS 1.1 таких обмежень не встановлює, тож це дефекти застосунку. Щоб кейси можна було виконати, у версії 2.2 логіни скорочено до 15–18 символів (`gt<код><NN>_<ДДММ-ГГХХ>`), а типові дані переведено на латиницю.

**Run 5.** Розпочато 28 кейсів: 13 passed, 13 failed; TC-004 — failed за даними версії 2.1 (кирилиця, BUG-020) і blocked за даними 2.2 (баланс $100.00 замість 515.50); TC-009 — blocked (типові дані не унікальні, пошук клієнта неоднозначний). Нові дефекти: BUG-020 (кирилиця), BUG-021 (неправильний пароль — внутрішня помилка), BUG-022 (оновлення профілю не зберігається). Ще 15 кейсів — blocked без виконання: 19.11.2026 demo відкриває рахунок при реєстрації з $100.00 замість 515.50 (налаштування Admin Page змінено, змінювати їх заборонено п. 5.4), а очікувані суми цих кейсів розраховані на 515.50; TC-021, TC-033 – TC-035, TC-050 заблоковані й з інших причин (немає даних, BUG-007, BUG-003).

**Run 6 — юзабіліті-сесія.** П'ять учасників, які раніше не користувались ParaBank (не з команд курсу), отримали лише логін і завдання, без підказок. TC-054 (U-10): обидві операції виконали всі, але за ≤ 300 с — лише 2 з 5 (148 – 599 с) — failed, BUG-023. Час — зі слів учасників, приблизний; таблиця — аркуш Usability журналу.
